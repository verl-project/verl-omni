# Qwen-Image Flow-DPPO V0/V1 tiny end-to-end smoke

Both entrypoints completed four training steps on two RTX 5090 GPUs (GPU 6–7) using the same random tiny Qwen-Image checkpoint, BF16 LoRA rank 8, 256×256 images, four denoising steps, two prompts per batch, two images per prompt, and the JPEG rule reward. The test used base commit `0fb3c91` and the existing `0z5a` environment (PyTorch 2.13.0+cu130, vLLM 0.28.0, vLLM-Omni 0.28.0rc1, verl 0.10.0.dev0). No packages were changed.

| Entry | Step 1, s | Steps 2–4 median, s | Throughput vs V0 | Final reward mean |
| --- | ---: | ---: | ---: | ---: |
| V0 | 31.928 | 6.650 | 1.00× | -0.063500 |
| V1 sync | 39.875 | 8.104 | 0.82× | -0.063519 |

The ratio is V0 median step time divided by V1 median step time; the tiny V1 run was slower. All eight actor losses were finite and all gradient norms were positive. [Per-step metrics](train_metrics.csv) contain the measured values. Step 1 includes queue and engine warmup. Three later steps are too few to predict full-model throughput.

Both runs used the repository OCR recipe scripts with identical smoke overrides: `trainer.n_gpus_per_node=2`, `trainer.total_training_steps=4`, `data.train_batch_size=2`, `rollout.n=2`, actor mini batch 2 and micro batch 1, rollout and reference log-prob micro batch 1, `rollout.pipeline.num_inference_steps=4`, `rollout.pipeline.height=256`, `rollout.pipeline.width=256`, `rollout.enforce_eager=true`, native actor attention, TORCH_SDPA rollout attention, `reward.reward_model.enable=false`, no custom reward function, console logging, and checkpoint/validation frequencies of `-1`. The source data were generated by `tests/special_e2e/create_dummy_diffusion_data.py` with `jpeg_compressibility` as the data source; the checkpoint came from `tests/special_e2e/build_qwen_image_tiny_random.py`.

This tiny smoke verifies the V1 training path with the Flow-DPPO loss. The pretrained OCR run below measures the full model and reward.

## Full pretrained Qwen-Image OCR run

Both modes completed real OCR training with the pretrained Qwen-Image policy and Qwen3-VL-8B-Instruct reward model on RTX 5090 GPUs. The matched layout used two actor/rollout GPUs (TP 2), one separate reward GPU (TP 1), BF16 LoRA rank 64, batch size 4, two images per prompt, 512×512 images, and ten denoising steps. Actor FSDP offload and rollout layerwise offload fit the model on 32 GiB cards. V0 ran on physical GPUs 0,1,2 for 20 steps; V1 sync ran on 1,2,3 for 100 steps. Both used the same dataset and OCR reward. The V1 run saved a checkpoint every 20 steps and retained only the latest completed one.

| Mode | Compared steps | Mean step, s | Median step, s | Mean-time speed vs V0 | Median-time speed vs V0 |
| --- | ---: | ---: | ---: | ---: | ---: |
| V0 | 1–19 | 117.003 | 96.643 | 1.000× | 1.000× |
| V1 sync | 1–19 | 114.199 | 96.931 | 1.025× | 0.997× |

The ratios divide V0 time by V1 time. They use the trainer's `timing_s/step` for the same 19-step window, before the first V1 checkpoint at step 20. This metric excludes model initialization and validation but includes checkpoint saves on saving steps. Across all 100 V1 steps, including five saves, mean step time was 111.569 s and median was 96.238 s. Shared-host activity varied between runs, and the matched median shows no speed gain.

## Lower-learning-rate V1 candidate

A separate V1 run used a learning rate of `3e-5` and four images per prompt on physical GPUs 0,1,2. It completed 40 real OCR training steps, validating and saving every ten steps. All 40 actor losses and gradient norms were finite. Its 32-row held-out OCR reward means were:

| Step | Validation reward |
| ---: | ---: |
| 0 | 0.760039 |
| 10 | 0.757055 |
| 20 | 0.783733 |
| 30 | 0.762087 |
| 40 | 0.792931 |

The final value exceeded the initial value by 0.032892, but the step-20 gain did not persist at step 30. Mean training rewards for steps 1–10, 11–20, 21–30, and 31–40 were 0.726548, 0.762745, 0.720088, and 0.691712. This run does not establish sustained held-out improvement or convergence. Its 39 pre-final-step training times averaged 196.313 s, with a median of 174.294 s; its four-image workload is different from the two-image V0/V1 speed comparison above.
