# Qwen-Image GRPO-Guard V0/V1 tiny end-to-end smoke

Both entrypoints completed four training steps on two RTX 5090 GPUs (GPU 6–7) using the same random tiny Qwen-Image checkpoint, BF16 LoRA rank 8, 256×256 images, four denoising steps, two prompts per batch, two images per prompt, and the JPEG rule reward. The test used base commit `0fb3c91` and the existing `0z5a` environment (PyTorch 2.13.0+cu130, vLLM 0.28.0, vLLM-Omni 0.28.0rc1, verl 0.10.0.dev0). No packages were changed.

| Entry | Step 1, s | Steps 2–4 median, s | Throughput vs V0 | Final reward mean |
| --- | ---: | ---: | ---: | ---: |
| V0 | 33.830 | 6.329 | 1.00× | -0.063471 |
| V1 sync | 39.178 | 8.112 | 0.78× | -0.063497 |

The ratio is V0 median step time divided by V1 median step time; the tiny V1 run was slower. All eight actor losses were finite and all gradient norms were positive. [Per-step metrics](train_metrics.csv) contain the measured values. `actor/ratio_std` was `nan` in both runs because the tiny micro batch left a single ratio for this diagnostic; the loss and gradient remained finite. Step 1 includes queue and engine warmup. Three later steps are too few to predict full-model throughput.

Both runs used the repository OCR recipe scripts with identical smoke overrides: `trainer.n_gpus_per_node=2`, `trainer.total_training_steps=4`, `data.train_batch_size=2`, `rollout.n=2`, actor mini batch 2 and micro batch 1, rollout and reference log-prob micro batch 1, `rollout.pipeline.num_inference_steps=4`, `rollout.pipeline.height=256`, `rollout.pipeline.width=256`, `rollout.enforce_eager=true`, native actor attention, TORCH_SDPA rollout attention, `reward.reward_model.enable=false`, no custom reward function, console logging, and checkpoint/validation frequencies of `-1`. The source data were generated by `tests/special_e2e/create_dummy_diffusion_data.py` with `jpeg_compressibility` as the data source; the checkpoint came from `tests/special_e2e/build_qwen_image_tiny_random.py`.

This tiny smoke verifies the V1 training path with the GRPO-Guard loss. The pretrained OCR measurements follow.

## Full pretrained Qwen-Image OCR run

Both V0 and V1 sync completed 100 steps with Qwen-Image and the Qwen3-VL-8B-Instruct OCR reward model on physical GPUs 0,1,2. They used two actor/rollout GPUs (TP 2), one separate reward GPU (TP 1), BF16 LoRA rank 64, four prompts per batch, two images per prompt, a learning rate of `3e-4`, and 512×512 images with ten denoising steps. FSDP2 CPU offload and rollout layerwise offload fit the workload on RTX 5090 cards. All actor losses and gradient norms were finite. A separate 20-step V0 pilot on GPUs 0,2,3 also completed; its validation reward was 0.805608 at step 0 and 0.729497 at step 20.

V1 was slower in this measurement; shared-host activity varied between runs.
